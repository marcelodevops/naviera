## Changed files

1. **src/scripts/site.js**
   - Menu state centralized in `setMenu(open)`, which now also syncs `aria-expanded` and the toggle's
     `aria-label` ("Abrir menú"/"Cerrar menú") alongside the `open` class and icon.
   - Mobile menu link click closes the menu and, on keyboard activation only (`event.detail === 0`),
     restores focus to `#menuToggle`. Pointer selection behavior is unchanged (NAV-008 confirmed all six
     pointer actions work), so no unexpected focus ring is introduced for taps.
   - Anchor handler `a[href^="#"]` now reads `href` and returns early on `''`/`'#'` before binding. This
     removes the uncaught `document.querySelector('#')` SyntaxError on brand clicks (NAV-006 defect 1);
     default jump-to-top still occurs for `href="#"`.
   - Kept `target.scrollIntoView({ behavior: 'smooth', block: 'start' })`; header clearance now comes from
     CSS `scroll-padding-top` (below), which `scrollIntoView` honors, instead of a magic pixel offset here.

2. **src/components/layout/Navigation.astro**
   - `#menuToggle` button gains `aria-controls="mobileMenu"` and `aria-expanded="false"` (initial closed
     state; JS keeps it in sync).

3. **src/styles/global.css**
   - `.mobile-menu` closed state adds `visibility: hidden` with a `visibility 0s linear 0.4s` delay so the
     max-height collapse stays visible; `.mobile-menu.open` sets `visibility: visible` (0s). This makes the
     closed menu genuinely non-focusable and removed from the a11y tree and hides the measured 18px
     closed strip (NAV-008 finding 3), synchronized with the open state.
   - Added fixed-header clearance: `html { scroll-padding-top: 152px; }` and
     `@media (min-width: 768px) { html { scroll-padding-top: 126px; } }`. 152px covers NAV-008's measured
     144px mobile closed-header edge with 8px clearance; the mobile menu is `md:hidden` so desktop only
     needs the pill (~118px edge) cleared, hence 126px.

4. **tests/navigation.test.js** (new regression check, ownership-allowed)
   - Four source-invariant assertions mirroring `departure.test.js` style (readFileSync + regex): brand
     `href="#"` preserved in nav+footer; anchor handler guards `href === '#'`; toggle exposes
     `aria-controls`/`aria-expanded` and JS syncs `aria-expanded` and restores focus; `.mobile-menu`
     closed→`visibility:hidden`, open→`visibility:visible`, and `html` has `scroll-padding-top`.

## Design notes

- `scroll-padding-top` on the root scroll container is the shared clearance both anchor `scrollIntoView`
  and browser-initiated focus scroll-into-view use, so the footer-brand-behind-pill case (NAV-008 finding 2)
  and the mobile anchor-label case (finding 1) are addressed without moving the fixed pill or the footer.
  This is intended, not a separate per-element hack — it must be confirmed by runtime focus-scroll behavior.
